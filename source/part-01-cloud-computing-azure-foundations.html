Part 1 — Cloud Computing & Azure Foundations

🎯 Goal: Build the vocabulary and mental model you need before touching the Azure Portal — what cloud computing actually means, how Azure bills you, and how Azure keeps things running when hardware fails.

🗺️ Concept Map

flowchart LR CC["Cloud Computing"] --> DM["Deployment Models\n(Public/Private/Hybrid/Multi)"] CC --> SM["Service Models\n(IaaS/PaaS/SaaS)"] CC --> Bill["Billing Model\n(CapEx vs OpEx)"] CC --> SR["Shared Responsibility"] CC --> GI["Global Infrastructure"] GI --> Reg["Region"] GI --> AZ["Availability Zone"] GI --> RP["Region Pair"] GI --> AS["Availability Set"]

1.1 What is Cloud Computing?

Cloud computing means renting IT resources — virtual machines, storage, databases, networking — over the internet, instead of buying and running your own physical servers.

Microsoft Azure owns huge data centers around the world. Instead of your company buying servers, switches, and firewalls, you simply "rent" what you need, whenever you need it, from Azure.

🏢 Real Project Example: A company wants to host an SCM (Source Code Management) application. Instead of buying physical servers, they create a Virtual Machine, a SQL Database, and a Storage Account inside Azure. Developers deploy the app; the operations team manages the infrastructure — with zero physical hardware involved.

Why companies use the cloud: - High availability — apps stay up even if hardware fails - Elastic scalability — add more power in minutes, not months - Built-in security and compliance tooling - Backup and disaster recovery baked in - Pay only for what you actually use - Deploy in minutes instead of weeks of procurement

🧠 Interview Angle: "Cloud Computing is the delivery of computing services — VMs, storage, networking, databases, and applications — over the internet. It lets organizations reduce hardware cost, scale on demand, and pay only for what they consume."

1.2 Cloud Deployment Models

There are four ways to deploy cloud resources, and picking the right one is a common interview scenario question.

flowchart TD Q{Where should this app live?} Q -->|Provider owns everything| Pub["Public Cloud\n(Azure, AWS, GCP)"] Q -->|We own everything| Priv["Private Cloud\n(Our own data center)"] Q -->|Some here, some there| Hyb["Hybrid Cloud\n(On-prem + Azure)"] Q -->|Spread across providers| Multi["Multi-Cloud\n(Azure + AWS + GCP)"]
Model Who owns the infrastructure Typical Use Case
Public Cloud Cloud provider (Microsoft) Startups, new apps — no hardware cost, fast deployment
Private Cloud Your own company Banks / regulated industries — full control, high cost
Hybrid Cloud Both (connected via VPN/ExpressRoute) Enterprises migrating slowly — DB stays on-prem, app runs in Azure
Multi-Cloud Several providers at once Risk-spreading — app on Azure, backup on AWS, analytics on GCP

💡 Tip: Companies choose Hybrid Cloud most often in real enterprise projects — they can't migrate everything overnight, so some systems remain on-premises while new workloads move to Azure.

1.3 Cloud Service Models — IaaS vs PaaS vs SaaS

This is one of the most frequently asked fundamentals questions in any Azure interview.

Model You manage Azure manages Examples
IaaS (Infrastructure as a Service) VM, OS, apps, security inside VM Physical servers, storage, network, hypervisor Azure VM, Virtual Network, Managed Disk, Load Balancer
PaaS (Platform as a Service) Just your application & data OS, patching, runtime App Service, Azure SQL Database, Azure Functions
SaaS (Software as a Service) Nothing — just use the app Everything Microsoft 365, Outlook, Teams, Dynamics 365

🏢 Real Project Example: Terraform creates a VM (IaaS) → DevOps installs Nginx → developers deploy their app. Versus: developers push code straight to App Service (PaaS) — no patching, no OS management needed.

1.5 The Shared Responsibility Model

Security in the cloud is shared between Microsoft and the customer — and exactly where that line sits depends on the service model (IaaS/PaaS/SaaS).

flowchart LR subgraph MS["Microsoft always manages"] m1[Physical Data Center] m2[Networking Hardware] m3[Power & Cooling] m4[Host / Hypervisor] end subgraph CU["Customer always manages"] c1[Identity & Access / RBAC] c2[Data Classification] c3[Application Logic] c4["OS (only on IaaS)"] c5[Secrets & Keys] end MS -.shared boundary shifts by service model.-> CU

⚠️ Common Mistake: If a VM gets hacked because of a weak admin password, Microsoft is not responsible — the customer is, because identity and OS-level security are the customer's job on IaaS.

🧠 Interview Angle: "Who manages the Operating System in an Azure VM?" → "The customer. Azure VM is IaaS, so Azure manages the physical infrastructure, and the customer manages the OS and everything above it."

1.6 Azure Global Infrastructure

Azure's physical footprint has a hierarchy of its own — separate from the resource hierarchy you'll see in Part 2.

flowchart TD Geo["Geography\n(e.g. Asia, Europe)"] --> Reg["Region\n(e.g. Central India)"] Reg --> AZ["Availability Zone\n(physically separate data centers)"] AZ --> DC["Data Center"]
Term Meaning Example
Geography A large area respecting data-residency/compliance boundaries Asia, Europe, North America
Region A set of data centers within a geography Central India, West Europe, East US
Availability Zone (AZ) Physically separate data centers within one region, each with independent power, cooling, and networking Zone 1, Zone 2, Zone 3 in Central India
Region Pair Two regions paired together for disaster recovery Central India ↔ South India

Why region choice matters: latency, compliance/data-residency laws, disaster recovery options, and cost all vary by region.

💡 Tip for interviews: Always say "deploy resources close to your users" — this is the standard answer for "why does region matter?"

1.7 Availability Zone vs Availability Set

Both protect your VMs from downtime — but at different levels, and this comparison is a favorite interview question.

flowchart TD subgraph AZdiag["Availability Zone — protects against Data Center failure"] direction LR z1["Zone 1\n(own power/cooling/network)"] z2["Zone 2\n(own power/cooling/network)"] z3["Zone 3\n(own power/cooling/network)"] end subgraph ASdiag["Availability Set — protects against Rack/Hardware failure"] direction LR fd1["Fault Domain 0"] fd2["Fault Domain 1"] ud1["Update Domain 0"] ud2["Update Domain 1"] end
Availability Zone Availability Set
Protects against Entire data center failure Hardware rack failure within one data center
Location Different physical data centers Same data center
Availability level Highest (99.99% SLA) Medium (99.95% SLA)
Best for Production workloads Legacy / smaller apps
Uses Independent power, cooling, network per zone Fault Domains + Update Domains

Fault Domain: a group of VMs on different physical hardware/racks — if one rack fails, VMs in other fault domains keep running. Update Domain: Azure patches one update-domain group of VMs at a time, so the rest of your app keeps serving traffic during planned maintenance.

✅ Part 1 Best Practices

  • Choose Hybrid Cloud when migration must happen gradually, not overnight.
  • Default to PaaS (App Service, Azure SQL) when you don't want to manage OS patching.
  • Always deploy production workloads across multiple Availability Zones, not just an Availability Set.
  • Pick your Region based on where your users are and any data-residency/compliance requirements.

🧠 Part 1 — Interview Questions

What is Cloud Computing?

Cloud Computing is the delivery of computing services — virtual machines, storage, networking, databases, and applications — over the internet. It lets organizations reduce hardware cost, increase scalability, improve availability, and pay only for the resources they use.

What is Azure?

Azure is Microsoft's public cloud platform. It provides on-demand computing, storage, networking, database, and application services from Microsoft-owned data centers around the world.

What is Public Cloud?

A deployment model where the infrastructure is owned and operated by a cloud provider (like Microsoft), and customers rent resources instead of owning hardware. Examples: Azure, AWS, GCP.

What is Hybrid Cloud?

A combination of Public Cloud and Private/On-Premises infrastructure, connected via VPN or ExpressRoute. Companies use it when they can't migrate everything to the cloud at once.

What is Multi-Cloud?

Using more than one cloud provider at the same time — for example, running the application on Azure, storing backups in AWS, and running analytics on Google Cloud — usually to reduce vendor lock-in or risk.

What is the difference between IaaS, PaaS, and SaaS?

IaaS gives you raw infrastructure (VMs, networking) and you manage the OS and app. PaaS gives you a managed platform (like App Service) where you only manage your app and data. SaaS gives you ready-to-use software (like Outlook) where you manage nothing.

What is the Shared Responsibility Model?

It defines which security tasks Microsoft handles (physical data center, hardware, hypervisor) and which the customer handles (identity, data, application, and — on IaaS — the OS). The exact split shifts depending on whether you're using IaaS, PaaS, or SaaS.

What is the difference between CapEx and OpEx?

CapEx means paying upfront to buy hardware you own. OpEx means paying for what you use, over time, without owning anything. Azure follows the OpEx model.

What is an Azure Region?

A geographic location that contains one or more data centers, connected by a low-latency network. Examples: Central India, East US, West Europe.

What is an Availability Zone?

A physically separate data center within the same Azure region, with its own independent power, cooling, and networking — used to protect applications from a full data-center failure.

What is an Availability Set?

A logical grouping for VMs that spreads them across multiple Fault Domains (different hardware) and Update Domains (patched at different times) within a single data center, protecting against hardware failure and planned maintenance downtime.

What is the difference between Region and Availability Zone?

A Region is a broad geographic location containing multiple data centers. An Availability Zone is one specific, physically isolated data center (or group of data centers) within that region.

What is the difference between Availability Set and Availability Zone?

Availability Set protects against hardware/rack failure within a single data center. Availability Zone protects against failure of an entire data center by spreading VMs across physically separate ones. Availability Zones offer higher availability.

🧩 Part 1 — Scenario-Based Questions

Your application is running on one VM. Suddenly the data center goes down. How can you avoid downtime in the future?

Deploy the application across multiple Availability Zones. If one zone fails, the application keeps running in another zone with no downtime.

Your company has an old data center and wants to move to Azure slowly. Which deployment model do you recommend?

Hybrid Cloud. Existing applications can keep running on-premises while new workloads are deployed in Azure, connected through VPN or ExpressRoute.

Why does Azure charge monthly instead of asking customers to buy servers?

Azure follows the Operational Expenditure (OpEx) model — customers pay only for the resources they use, which removes the need for large upfront hardware investment.

Your application is deployed on Azure App Service. Who is responsible for OS patching?

Microsoft. App Service is a PaaS offering, so Azure manages the operating system and the underlying platform — the customer only manages the application and its data.

📋 Part 1 — Quick Revision

  • Cloud = IT resources delivered over the internet.
  • Public Cloud = Azure manages the infrastructure. Private Cloud = you manage it. Hybrid = both, connected. Multi-Cloud = several providers at once.
  • IaaS = you manage OS + app. PaaS = you manage app only. SaaS = ready-to-use software.
  • CapEx = buy hardware once. OpEx = pay as you go (Azure's model).
  • Shared Responsibility = Microsoft secures the cloud; you secure what's in the cloud.
  • Region = geographic location with 1+ data centers. Availability Zone = separate data centers inside one region. Region Pair = two regions paired for disaster recovery.
  • Availability Set = protects VMs from hardware failure in one data center. Availability Zone = protects from entire data center failure — the stronger guarantee.
