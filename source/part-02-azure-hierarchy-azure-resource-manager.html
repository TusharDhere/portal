Part 2 — Azure Hierarchy & Azure Resource Manager

🎯 Goal: Understand how Azure organizes resources in an enterprise environment. This is the single most important concept for a Landing Zone — almost everything else (governance, cost tracking, security) attaches to this hierarchy.

🗺️ Concept Map

flowchart TD Tenant["Azure Tenant\n(your organization)"] --> MG["Management Group\n(groups subscriptions)"] MG --> Sub["Subscription\n(billing boundary)"] Sub --> RG["Resource Group\n(logical container)"] RG --> Res["Resources\n(VM, Storage, VNet...)"] Res -.deployed via.-> ARM["Azure Resource Manager"] ARM --> RP["Resource Provider\n(Microsoft.Compute, Microsoft.Storage...)"]

2.1 Why Does Azure Need a Hierarchy?

Without a hierarchy, at enterprise scale you'd have no way to manage users, control cost, enforce security standards, or apply policy consistently. The hierarchy is what makes Azure governable.

🏢 Real Project Example: ABC Company has businesses in India, USA, and Europe. Each business has multiple Azure subscriptions. Each subscription contains multiple Resource Groups. Each Resource Group contains multiple resources. This nesting is what keeps a 500-resource enterprise environment manageable.

2.2 Azure Tenant

The Tenant is the highest level in Azure — it represents your entire organization. Everything (users, subscriptions, apps) lives inside one tenant.

  • Think of it as your company's Azure/Microsoft 365 account.
  • Identified by a domain like abc.onmicrosoft.com.
  • Contains: Users, Groups, Applications, Service Principals, Managed Identities, Management Groups, and Subscriptions.

🏢 Real Project Example: Your company uses Microsoft 365. Employees log in with amit@company.com — that user exists inside Microsoft Entra ID, which belongs to your Tenant.

2.3 Management Group

A Management Group organizes multiple Subscriptions so you can apply governance (Policies, RBAC) once, at the top, instead of subscription-by-subscription.

🏢 Real Project Example: A company has 100 subscriptions. Applying a security policy to each one individually is painful. Instead: create one Management Group → apply the policy once → it automatically inherits down to every subscription inside it.

flowchart TD Root["Tenant Root Group"] --> MGProd["Management Group:\nProduction"] Root --> MGNonProd["Management Group:\nNon-Production"] MGProd --> SubIN["Subscription:\nProd-India"] MGProd --> SubUS["Subscription:\nProd-USA"] MGNonProd --> SubDev["Subscription:\nDev"] MGNonProd --> SubQA["Subscription:\nQA"]

✅ Best Practice: Never place subscriptions directly under the Root — always organize through Management Groups (a common real-world pattern is: Production, Non-Production, Sandbox).

2.4 Subscription

A Subscription is a billing and resource-isolation boundary. Every Azure resource belongs to exactly one subscription.

A Subscription provides: Billing separation, resource Quotas, Access Control, and Resource Isolation.

🏢 Real Project Example: Production resources should never be deployed into a Development subscription — billing, security, and governance would all bleed together. Keep them separate: Production, Development, Testing, Shared Services.

🧠 Interview Angle: "Can one Resource Group belong to multiple subscriptions?" → "No. A Resource Group belongs to exactly one subscription."

2.5 Resource Group (RG)

A Resource Group is a logical container that holds related Azure resources — the level where most day-to-day management happens.

🏢 Real Project Example: For an "Inventory System" application, you'd create rg-prod-inventory containing its VM, SQL Database, Storage Account, Key Vault, NSG, and Application Gateway — everything the app needs, together in one place.

Benefits: easier management, monitoring, deletion (delete the RG → everything inside is deleted), RBAC scoping, Tags, and Locks.

⚠️ Common Mistake: Mixing multiple unrelated applications inside one Resource Group. Keep one application = one Resource Group as a rule of thumb.

🧠 Interview Angle: "Can resources from different Azure regions live in the same Resource Group?" → "Yes — a Resource Group is a logical container, not a physical/regional boundary."

2.6 Azure Resources

Resources are the actual services you use: VM, Storage Account, Virtual Network, NSG, SQL Database, Key Vault, Load Balancer, AKS, App Service, and so on.

2.7 Azure Resource Manager (ARM)

ARM is the deployment and management engine of Azure. Every single request to create, update, or delete a resource — no matter which tool you used — goes through ARM.

flowchart LR Portal["Azure Portal"] --> ARM CLI["Azure CLI"] --> ARM PS["PowerShell"] --> ARM TF["Terraform"] --> ARM ARMTpl["ARM / Bicep Template"] --> ARM ARM["Azure Resource\nManager (ARM)"] --> Validate["Validates request"] Validate --> RP["Routes to correct\nResource Provider"] RP --> Created["Resource Created"]

Why ARM matters: Authentication, Authorization, deployment orchestration, dependency management, resource tracking, and where RBAC/Tags/Locks/Policies are actually enforced.

🏢 Real Project Example: When you run terraform apply, Terraform does not create the VM directly — it sends an API request to ARM, and ARM creates the VM. This is a very common interview trap.

🧠 Interview Angle: "Does Terraform directly create Azure resources?" → "No. Terraform calls the Azure Resource Manager API. ARM validates the request and creates the resource."

2.8 Resource Provider

Every Azure service belongs to a Resource Provider — a namespace that actually implements that service.

Resource Resource Provider
Virtual Machine Microsoft.Compute
Storage Account Microsoft.Storage
Virtual Network Microsoft.Network
SQL Database Microsoft.Sql
Key Vault Microsoft.KeyVault

Flow: Create VM request → ARM → routes to Microsoft.Compute → VM created.

⚠️ Common Mistake: If a Resource Provider isn't registered on your subscription, deployment fails with a provider-registration error — this is a real troubleshooting scenario interviewers ask about.

2.9 Control Plane vs Data Plane

One of the most important — and most commonly misunderstood — Azure concepts.

Control Plane Data Plane
Purpose Manage the resource itself Access the data inside the resource
Examples Create VM, delete Storage, assign RBAC, apply Tags Upload a blob, connect to a VM, query a SQL database
Tools Azure Portal, CLI, ARM, Terraform, PowerShell App SDKs, storage clients, RDP/SSH
flowchart LR subgraph CP["Control Plane"] direction TB cp1["Create Storage Account"] end subgraph DP["Data Plane"] direction TB dp1["Upload a file into that Storage Account"] end CP --> DP

🧠 Interview Angle: "Control Plane manages Azure resources. Data Plane interacts with the data stored inside those resources."

2.10 Naming Convention

Large enterprises always enforce naming standards — it's both a governance and an interview favorite.

❌ Bad ✅ Good
vm1 vm-prod-web-001
storage1 rg-prod-network
test123 vnet-prod-centralindia

Benefits: easy identification, automation-friendly, faster troubleshooting.

2.11 Azure Tags

Tags are key-value pairs attached to resources for cost tracking, automation, filtering, and governance.

Environment = Production
Project     = SCM
Owner       = DevOps
Department  = IT
CostCenter  = 1001

🏢 Real Project Example: The Finance team wants an itemized Azure bill. Filter by Environment=Production in Cost Management, and you instantly get cost broken down by tag.

✅ Best Practice: Every resource should carry at minimum: Environment, Application, Owner, CostCenter, BusinessUnit.

2.12 Resource Locks

Locks prevent accidental deletion or modification of critical resources.

Lock Type Effect
ReadOnly Users can view but cannot modify or delete
Delete Users can still modify, but cannot delete

🏢 Real Project Example: Apply a Delete Lock on a production Storage Account so nobody can accidentally delete it — even with full Contributor access.

RBAC Resource Lock
Controls Who can access What can happen to the resource
Basis Identity-based Resource-based
Purpose Security Protection from accidents

🖥️ Hands-On: Create a Resource Group in the Azure Portal

  1. Sign in to the Azure Portal.
  2. In the top search bar, type "Resource groups" and select it.
  3. Select + Create.

  1. Choose your Subscription, type a Resource group name (e.g. rg-prod-inventory), and pick a Region.

  1. Select Review + Create, then Create.
  2. Your new Resource Group now appears in the list — this is where you'll create every resource for this application going forward.

💡 Try it yourself: Go to your new Resource Group → Locks → Add → select Delete lock. Now try deleting the Resource Group — Azure will block you until you remove the lock first.

🖥️ Hands-On: Create a Management Group

  1. In the Portal search bar, type "Management groups".
  2. Select + Add management group.

  1. Enter a unique Management Group ID (cannot be changed later) and an optional Display name.

  1. Select Save. You can now drag-and-drop subscriptions into this group from the Management Groups tree view.

✅ Part 2 Best Practices

  • ✅ Keep Production and Non-Production in separate subscriptions.
  • ✅ Use Management Groups for enterprise-wide governance.
  • ✅ One application = one Resource Group.
  • ✅ Follow a consistent naming convention.
  • ✅ Apply mandatory Tags on every resource.
  • ✅ Put Delete Locks on all production-critical resources.
  • ✅ Deploy through ARM/Terraform, not manual clicks, wherever possible.

🧠 Part 2 — Interview Questions

What is Azure Hierarchy?

The layered structure Azure uses to organize resources: Tenant → Management Group → Subscription → Resource Group → Resources. Each layer exists for a specific governance or billing purpose.

What is Azure Tenant?

The highest-level container in Azure. It represents an organization and stores users, groups, applications, identities, management groups, and subscriptions.

What is a Management Group?

A container used to organize multiple Azure subscriptions so that governance controls — like RBAC and Azure Policy — can be applied once and inherited automatically by every subscription underneath.

What is a Subscription?

A billing and resource-isolation boundary. Every Azure resource belongs to exactly one subscription, which provides billing, quota, access control, and isolation.

What is a Resource Group?

A logical container that groups related Azure resources together for easier management, monitoring, RBAC, tagging, and deletion.

What is Azure Resource Manager?

The deployment and management service of Azure. Every request — from the Portal, CLI, PowerShell, or Terraform — goes through ARM, which validates it and routes it to the right Resource Provider.

What is a Resource Provider?

A namespace responsible for a specific Azure service (e.g. Microsoft.Compute for VMs, Microsoft.Storage for Storage Accounts). ARM routes requests to the correct provider to actually create the resource.

What is the difference between Control Plane and Data Plane?

Control Plane manages the resource itself (create, delete, configure, assign RBAC). Data Plane accesses the data or functionality inside that resource (upload a file, query a database, connect to a VM).

What are Azure Tags?

Key-value pairs attached to resources, used for cost tracking, automation, filtering, and governance reporting.

What are Resource Locks?

A mechanism to prevent accidental deletion (Delete lock) or modification (ReadOnly lock) of critical resources.

🧩 Part 2 — Scenario-Based Questions

Your company has 60 Azure subscriptions. You need to apply a security policy to all of them. What is the best approach?

Create a Management Group, move the subscriptions under it, and apply the Azure Policy at the Management Group level — it will automatically apply to every child subscription.

A developer accidentally deleted a production Storage Account. How could you prevent this in the future?

Apply a Delete Lock to the production Storage Account. This blocks accidental deletion while still allowing normal modifications.

Your finance team wants separate Azure costs for Production and Development. How would you design it?

Create separate Production and Development subscriptions, and use Tags like Environment=Production and Environment=Development for detailed cost reporting within Cost Management.

Your Terraform deployment fails with a Resource Provider registration error. What will you check?

Verify whether the required Resource Provider (e.g. Microsoft.Compute or Microsoft.Network) is registered on the subscription. If not, register it and re-run the deployment.

📋 Part 2 — Quick Revision

  • Tenant = organization boundary.
  • Management Group = organizes multiple subscriptions, applies governance centrally.
  • Subscription = billing, quota, and access boundary.
  • Resource Group = logical container for resources.
  • ARM = the engine that deploys and manages every Azure resource.
  • Resource Provider = service-specific handler, like Microsoft.Compute.
  • Control Plane = manage the resource. Data Plane = use the data inside it.
  • Tags = key-value pairs for cost & governance tracking.
  • Locks = ReadOnly (no changes) or Delete (no deletion).
