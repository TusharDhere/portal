Part 5 — Networking Foundations

🎯 Goal: Understand Azure networking from an enterprise and interview perspective. This is the biggest and most important prerequisite module — a strong grip on networking makes ~50% of Landing Zone concepts click automatically.

🗺️ Concept Map

flowchart TD IP["IP Address / CIDR"] --> VNet["Virtual Network"] VNet --> Subnet["Subnet"] Subnet --> NIC["NIC"] Subnet --> NSG["NSG / ASG"] VNet --> Peer["VNet Peering"] VNet --> Hybrid["Hybrid Connectivity\n(VPN Gateway / ExpressRoute)"] VNet --> Outbound["Outbound Access\n(NAT Gateway)"] VNet --> FW["Azure Firewall"] VNet --> Bastion["Azure Bastion"] VNet --> PaaS["PaaS Access\n(Service / Private Endpoint)"] VNet --> LB["Traffic Distribution\n(Load Balancer / App Gateway\n/ Traffic Manager / Front Door)"]

5.1 IP Address & CIDR

An IP Address is a unique address identifying a device on a network.

Private IP Public IP
Reachable from Inside the VNet only The Internet
Uniqueness Reused across different VNets Globally unique
Example use Internal VM-to-VM communication SSH/RDP to a VM, a public website

CIDR defines a network's IP range. 10.0.0.0/16 ≈ 65,536 addresses. 10.0.1.0/24 ≈ 256 addresses.

✅ Best Practice: Plan your CIDR ranges carefully before deployment — resizing a VNet's address space later is difficult and disruptive.

5.2 Virtual Network (VNet) & Subnet

A VNet is your own private, isolated network inside Azure — all Azure resources communicate through it.

A Subnet divides one VNet into smaller networks for security and traffic isolation.

flowchart TD VNet["VNet: 10.0.0.0/16"] --> Web["Web Subnet\n10.0.1.0/24"] VNet --> App["App Subnet\n10.0.2.0/24"] VNet --> DB["Database Subnet\n10.0.3.0/24"] VNet --> Bas["Bastion Subnet"] VNet --> FwSub["Firewall Subnet"]

✅ Best Practice: Create separate subnets for Web, App, Database, Bastion, Firewall, and Application Gateway — never put everything in one flat subnet.

5.3 Network Interface (NIC)

The NIC is what connects a VM to a VNet — without it, a VM can't communicate at all. A NIC holds a Private IP, an optional Public IP, and an optional NSG.

flowchart LR VM["VM"] --> NIC["NIC"] --> Subnet["Subnet"] --> VNet["VNet"]

5.4 NSG & ASG

NSG (Network Security Group) acts like a firewall — it controls inbound and outbound traffic with Allow/Deny rules, applied to a Subnet or a NIC.

Allow SSH   (Port 22)
Allow HTTP  (Port 80)
Allow HTTPS (Port 443)
Deny Everything else

ASG (Application Security Group) groups VMs logically (e.g. "Web Servers") instead of by IP address, so NSG rules can reference the group name — much easier to manage at scale.

flowchart LR WebASG["Web ASG\n(VM1, VM2, VM3)"] -- "NSG rule: Allow" --> DBASG["Database ASG"]

5.5 User Defined Route (UDR)

Azure auto-creates routes by default, but you can override them with a UDR — commonly used to force all traffic through a firewall instead of going straight to the internet.

flowchart LR VM["VM"] -->|"default route (no UDR)"| Internet1["Internet"] VM2["VM (with UDR)"] --> FW["Azure Firewall"] --> Internet2["Internet"]

5.6 DNS & Private DNS Zone

DNS resolves a name like google.com into an IP address. Azure provides Azure DNS for public resolution and Private DNS Zones for internal name resolution — required alongside Private Endpoints, since no public DNS record exists for a privately-connected PaaS service.

5.7 VNet Peering

VNet Peering connects two VNets privately — resources communicate over Microsoft's backbone using private IPs, with low latency and high throughput.

flowchart LR A["VNet A"] <-->|Peering| B["VNet B"]

5.8 Hybrid Connectivity — VPN Gateway vs ExpressRoute

Both connect on-premises networks to Azure, but very differently.

VPN Gateway ExpressRoute
Connection Over the public Internet Private, dedicated connection
Cost Lower Higher
Speed / Latency Lower speed High speed, low latency
Typical user Smaller companies Large enterprises

🧠 Interview Angle: VPN Gateway is cheaper and good for smaller hybrid setups. ExpressRoute is the enterprise-grade choice when the internet isn't private or reliable enough.

5.9 NAT Gateway

NAT Gateway gives VMs outbound-only internet access (e.g. downloading updates) without needing a Public IP on the VM at all — no inbound access is possible.

5.10 Azure Firewall

A managed Layer 3–Layer 7 firewall service controlling inbound, outbound, and East-West (VNet-to-VNet) traffic using Application Rules, Network Rules, and DNAT.

flowchart LR Traffic["All Traffic"] --> AzFW["Azure Firewall"] --> Internet["Internet"]

5.11 Azure Bastion

Bastion provides secure RDP/SSH access to VMs directly through the Azure Portal — no Public IP needed on the VM, and no open RDP/SSH ports exposed to the internet.

5.12 Service Endpoint vs Private Endpoint

Both let VNet resources reach Azure PaaS services (like Storage) more securely than over the public internet — but they work very differently.

Service Endpoint Private Endpoint
PaaS service remains Public (but routed via Azure backbone) Fully private (gets its own private IP)
Gets a Private IP? No Yes
Security level Good Stronger
Path Azure backbone Azure backbone + fully private access

🧠 Interview Angle: "Difference between Service Endpoint and Private Endpoint?" → "A Service Endpoint routes traffic to a still-public service over Azure's backbone. A Private Endpoint gives the PaaS service an actual private IP inside your VNet, making it fully private."

5.13 Traffic Distribution — Load Balancer, App Gateway, Traffic Manager, Front Door

This four-way comparison is one of the single most common Azure networking interview questions.

flowchart TD Internet["Internet"] --> FD["Azure Front Door\n(Global, Layer 7)"] FD --> AGW["Application Gateway\n(Regional, Layer 7 + WAF)"] AGW --> LB["Load Balancer\n(Layer 4)"] LB --> WebVM["Web VM"] LB --> AppVM["App VM"] AppVM --> DB["Database"]
Service Layer Scope Use Case
Load Balancer L4 (TCP/UDP) Regional Distribute traffic across backend VMs; no SSL termination, no URL routing
Application Gateway L7 (HTTP/HTTPS) Regional SSL termination, URL-based routing, cookie affinity, WAF
Traffic Manager DNS-based Global Route users to the nearest/healthiest region using DNS (Priority, Performance, Weighted, Geographic)
Azure Front Door L7, Global Global Global load balancing + SSL offloading + caching + WAF + acceleration, in one service

🏢 Real Project Example: A company has apps in Central India and East US. Users should reach the nearest healthy region automatically → Azure Front Door (for HTTP/HTTPS apps needing WAF and performance features) or Traffic Manager (if only simple DNS-based regional routing is needed).

Enterprise Network Flow (Hub & Spoke style)

flowchart TD Internet["Internet"] --> FD["Azure Front Door"] FD --> AGW["Application Gateway (WAF)"] AGW --> LB["Load Balancer"] LB --> WebVM["Web VM"] WebVM --> AppVM["App VM"] AppVM --> DB["Database"]

✅ Part 5 Best Practices

  • ✅ Use Hub & Spoke architecture for enterprise networks.
  • ✅ Separate subnets for Web, App, DB, Bastion, Firewall, and Application Gateway.
  • ✅ Avoid Public IPs on production VMs.
  • ✅ Use Bastion for VM management instead of open RDP/SSH.
  • ✅ Use Private Endpoints for PaaS services wherever possible.
  • ✅ Write NSG rules with least-privilege in mind.
  • ✅ Route internet-bound traffic through Azure Firewall where required.
  • ✅ Use ExpressRoute for serious enterprise connectivity needs.
  • ✅ Plan CIDR ranges before you deploy anything.

🖥️ Hands-On: Create a Virtual Network in the Portal

  1. In the Portal search bar, type "Virtual networks" → select + Create.
  2. On the Basics tab, choose your Subscription and Resource Group, then name it (e.g. vnet-prod-centralindia) and pick a Region.
  3. On the IP Addresses tab, set the address space (e.g. 10.0.0.0/16) and add subnets (e.g. snet-web → 10.0.1.0/24, snet-app → 10.0.2.0/24).
  4. On the Security tab, optionally enable Azure Bastion, Azure Firewall, and DDoS Protection right from the creation wizard.
  5. Select Review + create, then Create.

💡 Try it yourself: After creating the VNet, go to Subnets → add a new subnet called snet-db → then go to Network Security Groups → create an NSG → attach it to snet-db → add a rule that only allows traffic from snet-app, denying everything else.

🧠 Part 5 — Interview Questions

What is a VNet?

A logically isolated private network in Azure that enables secure communication between Azure resources.

What is a Subnet?

A smaller network carved out of a VNet's address space, used to isolate and organize resources (Web, App, Database, etc.) for security and manageability.

What is the difference between Public IP and Private IP?

A Public IP is internet-accessible and globally unique — used for things like SSH/RDP or a public website. A Private IP is only reachable inside the VNet and is used for internal communication.

What is an NSG?

A Network Security Group — a firewall-like service that filters inbound and outbound traffic to a subnet or NIC using Allow/Deny rules.

What is Azure Bastion?

A managed service providing secure RDP/SSH access to VMs directly through the Azure Portal, without needing a Public IP on the VM or opening RDP/SSH ports to the internet.

What is Azure Firewall?

A managed, cloud-native firewall service (Layer 3–7) that controls inbound, outbound, and East-West traffic using application rules, network rules, and DNAT.

What is VNet Peering?

A way to privately connect two VNets so their resources communicate using private IPs over Azure's backbone network, with low latency.

What is a NAT Gateway?

A service that provides secure, scalable outbound-only internet access for resources in a subnet, without requiring a Public IP on each VM.

What is a Private Endpoint?

A network interface that gives an Azure PaaS service (like a Storage Account) a private IP address inside your VNet, making it accessible only from within that network.

What is the difference between Service Endpoint and Private Endpoint?

A Service Endpoint routes traffic to a PaaS service over the Azure backbone while the service remains publicly addressed. A Private Endpoint assigns the PaaS service an actual private IP inside your VNet, making it fully private — a stronger security posture.

🧩 Part 5 — Scenario-Based Questions

Your Linux VM should download updates from the internet but must not be accessible from the internet. What will you do?

Remove the Public IP from the VM and attach a NAT Gateway to its subnet. This allows outbound internet access while blocking all inbound access.

Your Storage Account should only be accessible from your VNet. How will you secure it?

Create a Private Endpoint for the Storage Account, configure a Private DNS Zone for name resolution, and disable public network access on the account.

Your company has applications in Central India and East US. Users should automatically connect to the nearest healthy region. Which service will you use?

Azure Front Door for HTTP/HTTPS applications — it provides global routing, health checks, WAF, and performance optimization. If only simple DNS-based regional routing is needed, Traffic Manager is also a valid option.

Developers need SSH access to production VMs, but security policy doesn't allow Public IPs. What will you implement?

Deploy Azure Bastion in the VNet and remove Public IPs from the VMs — developers connect securely through the Azure Portal via Bastion instead.

You need to expose a web application with SSL termination and URL-based routing. Which service will you choose?

Azure Application Gateway — a Layer 7 load balancer that supports SSL termination, URL-based routing, and Web Application Firewall (WAF).

📋 Part 5 — Quick Revision

  • VNet = private network. Subnet = a division of it.
  • NIC = connects a VM to the network.
  • Public IP = internet-reachable. Private IP = internal only.
  • NSG = filters traffic. ASG = logical VM grouping for NSG rules.
  • UDR = custom routing (e.g. force traffic through a firewall).
  • DNS = resolves names to IPs. Private DNS Zone = resolution for Private Endpoints.
  • VNet Peering = private connection between two VNets.
  • VPN Gateway = hybrid link over the internet. ExpressRoute = dedicated private hybrid link.
  • NAT Gateway = outbound-only internet access, no Public IP needed.
  • Azure Firewall = managed network firewall. Bastion = secure RDP/SSH with no Public IP.
  • Service Endpoint = secure but still-public PaaS access. Private Endpoint = fully private PaaS access.
  • Load Balancer = L4. Application Gateway = L7 + WAF. Traffic Manager = DNS-based global routing. Front Door = global L7 delivery + WAF + caching.
