Part 6 — Azure Storage

🎯 Goal: Understand Azure Storage architecture, redundancy options, and security — both direct-definition and scenario-based questions are extremely common here.

🗺️ Concept Map

flowchart TD SA["Storage Account"] --> Blob["Blob Storage"] SA --> Files["Azure Files"] SA --> Queue["Queue Storage"] SA --> Table["Table Storage"] SA --> Disk["Managed Disk"] SA --> Redundancy["Redundancy\n(LRS/ZRS/GRS/RA-GRS/GZRS)"] SA --> Security["Security\n(SAS, Keys, Firewall,\nPrivate Endpoint)"] SA --> Lifecycle["Lifecycle Management\n(Hot/Cool/Archive)"]

6.1 What is Azure Storage?

Azure Storage is Microsoft's cloud storage service for structured and unstructured data, with built-in high availability, scalability, security, backup, and disaster recovery.

🏢 Real Project Example: An SCM application stores invoices in Blob Storage, application logs in a Storage Account, VM disks as Managed Disks, and shared configuration files in Azure Files — all different storage services, all under the umbrella of "Azure Storage."

6.2 Storage Account

The Storage Account is the top-level container — every storage service (Blob, Files, Queue, Table) lives inside one.

flowchart TD SA["Storage Account"] --> B["Blob"] SA --> F["File"] SA --> Q["Queue"] SA --> T["Table"]

✅ Best Practice: Create separate Storage Accounts for Production, Development, Backup, and Logs — don't mix them.

6.3 The Four Storage Services

Service Stores Real Example
Blob Storage Unstructured data Images, videos, PDFs, backups, logs
Azure Files Fully managed shared file storage (SMB/NFS) 5 VMs all sharing the same config folder
Queue Storage Messages, for async app-to-app communication An order-processing background worker
Table Storage NoSQL structured (key-value) data Employee data, device info, logs

Blob Types

Type Used For
Block Blob Most common — images, documents, videos
Append Blob Application/audit logs (data only ever added to the end)
Page Blob Azure VM disks

🧠 Interview Angle: "Which blob type backs a VM disk?" → "Page Blob."

6.4 Managed Disk

Managed Disk is Azure-managed storage for VMs — Azure handles availability, scalability, and replication automatically.

Disk Type Performance Typical Use
Standard HDD Low cost, low performance Dev/test, backup
Standard SSD Balanced General purpose
Premium SSD High performance Production workloads
Ultra Disk Very high IOPS Mission-critical workloads (e.g. large SQL Server)

🧠 Interview Angle: "Which disk is recommended for a production SQL Server?" → "Premium SSD, or Ultra Disk for extreme performance requirements."

6.5 Storage Redundancy — LRS, ZRS, GRS, RA-GRS, GZRS

One of the most important interview topics in this whole course.

flowchart TD LRS["LRS\n3 copies, 1 data center"] --> ZRS["ZRS\n3 copies across\nAvailability Zones"] ZRS --> GRS["GRS\ncopied to a\npaired region"] GRS --> RAGRS["RA-GRS\nGRS + secondary\nregion is readable"] RAGRS --> GZRS["GZRS\nZone redundancy +\nGeo replication\n(highest protection)"]
Type What it protects against
LRS (Locally Redundant Storage) Hardware failure — 3 copies within one data center
ZRS (Zone Redundant Storage) Data center failure — 3 copies across Availability Zones
GRS (Geo Redundant Storage) Regional disaster — replicated to a paired region
RA-GRS (Read-Access GRS) Same as GRS, plus the secondary region can be read
GZRS (Geo-Zone Redundant Storage) Zone failure and regional disaster — highest protection available

🧠 Interview Angle: "Which redundancy option gives the highest availability?" → "GZRS — it combines zone-level and region-level protection."

6.6 Storage Security — Access Keys vs SAS Token

Access Keys SAS Token (Shared Access Signature)
Access level Full access to the entire Storage Account Limited — specific permissions only
Duration Permanent until rotated Temporary — expires automatically
Recommended for apps? ❌ Avoid ✅ Preferred for external/temporary access

🏢 Real Project Example: Give a customer Read access to a file for 24 hours, using a SAS Token — access expires automatically, no manual cleanup needed.

🧠 Interview Angle: "Why use a SAS Token instead of an Access Key?" → "A SAS Token provides limited, time-bound access, while Access Keys grant full, permanent access to the entire Storage Account."

Other security layers: Encryption at Rest, Encryption in Transit, RBAC, Private Endpoint, Storage Firewall, Managed Identity.

6.7 Storage Tiers & Lifecycle Management

Tier Access frequency Storage cost Access/retrieval cost
Hot Frequent Higher Lower
Cool Infrequent Lower Higher
Archive Rare Lowest Highest (slow retrieval)

Lifecycle Management automates moving data between tiers (or deleting it) based on age — e.g. move to Cool after 30 days, Archive after 90 days, delete after 365 days.

🧠 Interview Angle: "Where should 5-year-old backup files be stored?" → "Archive Tier — rarely accessed, lowest storage cost."

6.8 Versioning & Soft Delete

  • Versioning — Azure keeps previous versions whenever a file changes, protecting against accidental overwrites.
  • Soft Delete — a deleted file isn't removed immediately; it can be restored within the retention window, protecting against accidental deletion.

6.9 Storage Firewall & Private Endpoint

Storage Firewall restricts network access — e.g. allow only your company VNet, block the public internet entirely.

Private Endpoint goes further, giving the Storage Account a private IP inside your VNet — no public internet path exists at all.

flowchart LR App["Application"] --> MI["Managed Identity"] --> PE["Private Endpoint"] --> SA["Storage Account"] --> Blob["Blob Storage"]

✅ Part 6 Best Practices

  • ✅ Use Private Endpoint for production Storage Accounts.
  • ✅ Disable Public Network Access wherever possible.
  • ✅ Use Managed Identity instead of Access Keys for application access.
  • ✅ Use SAS Tokens for temporary, external access needs.
  • ✅ Enable Soft Delete and Versioning for critical data.
  • ✅ Configure Lifecycle Management for cost control.
  • ✅ Choose the right redundancy (ZRS/GRS/GZRS) based on actual business continuity needs — don't default to the most expensive option unnecessarily.

🖥️ Hands-On: Create a Storage Account & Upload a Blob

  1. In the Portal search bar, type "Storage accounts" → + Create.
  2. Choose your Subscription and Resource Group, name the account (must be globally unique, lowercase, no spaces — e.g. stprodinventory001), pick a Region, and set Redundancy (start with LRS for dev, GRS/ZRS for production).
  3. Select Review + create, then Create.
  4. Once deployed, go to Containers → + Container → name it (e.g. invoices) → set access level to Private.
  5. Open the container → Upload → select a file from your computer.

💡 Try it yourself: Go to Networking on your Storage Account → switch Public network access to Disabled → then create a Private Endpoint instead, pointing it at your VNet. Notice how the Storage Account is now completely unreachable from the public internet.

🧠 Part 6 — Interview Questions

What is Azure Storage?

Microsoft's cloud storage service used to securely store structured and unstructured data with high availability, scalability, backup, and disaster recovery built in.

What is a Storage Account?

The top-level container for Azure Storage services — Blob, File, Queue, and Table storage are all created inside a Storage Account.

What is the difference between Blob Storage and Azure Files?

Blob Storage stores unstructured data like images and backups, accessed via REST/SDK. Azure Files provides fully managed shared file storage accessible over SMB or NFS, so multiple VMs can mount the same shared folder.

What is Queue Storage?

A messaging service used for asynchronous communication between application components — e.g. an order service pushing a message that a background worker later processes.

What is Table Storage?

A NoSQL key-value store used for structured data like employee records, device information, or logs.

What is Managed Disk?

Azure-managed storage for Virtual Machines, where Azure automatically handles availability, scalability, and replication.

What are Storage Tiers?

Hot, Cool, and Archive — access tiers that trade off storage cost against access cost, based on how frequently the data is used.

What is Soft Delete?

A protection feature where deleted data isn't removed immediately but kept for a retention period, allowing recovery from accidental deletion.

What is Versioning?

A feature that automatically keeps previous versions of a blob whenever it's modified, allowing recovery from accidental overwrites.

What is a SAS Token?

A Shared Access Signature — a time-limited, permission-scoped token that grants temporary access to Storage Account resources, without exposing the full Access Key.

🧩 Part 6 — Scenario-Based Questions

Your application needs to upload documents to Azure Storage securely without exposing the Storage Account to the internet. What will you do?

Create a Private Endpoint for the Storage Account, disable public network access, use Managed Identity for authentication, and configure a Private DNS Zone for name resolution.

A customer needs temporary access to download a file for the next 12 hours. How will you provide access?

Generate a SAS Token with read permission and a 12-hour expiry — access disappears automatically afterward.

Your company stores monthly backups for seven years. Which storage tier will you use?

The Archive Tier, since the backups are rarely accessed and minimizing long-term storage cost is the priority.

A developer accidentally deleted an important blob yesterday. How can you recover it?

If Soft Delete was enabled, restore the blob from within the retention period. If Versioning was also enabled, a previous version can be restored as well.

Your finance team asks why storage costs are increasing every month. How would you optimize costs?

Review storage usage patterns, move infrequently accessed data to Cool or Archive tiers via Lifecycle Management, remove unused data after approval, and verify the chosen redundancy level actually matches business requirements rather than defaulting to the most expensive option.

📋 Part 6 — Quick Revision

  • Storage Account = parent container for all storage services.
  • Blob Storage = unstructured data. Azure Files = shared file storage. Queue = messaging. Table = NoSQL data.
  • Managed Disk = storage for Azure VMs (HDD → Standard SSD → Premium SSD → Ultra Disk).
  • LRS = 3 copies, 1 data center. ZRS = across Availability Zones. GRS = replicated to paired region. RA-GRS = GRS + readable secondary. GZRS = zone + region protection (highest).
  • Access Keys = full access (avoid in apps). SAS Token = temporary, limited access (preferred).
  • Hot/Cool/Archive = access-frequency-based cost tiers.
  • Lifecycle Management = automatic tiering/cleanup by age.
  • Versioning = keeps old versions. Soft Delete = recovers deleted data.
  • Storage Firewall = restricts network access. Private Endpoint = gives storage a private IP inside your VNet.
