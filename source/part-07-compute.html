Part 7 — Compute

🎯 Goal: Understand Azure's compute services, when to use each one, and enterprise best practices. Interviewers rarely ask about just VMs — expect questions on availability, scalability, performance, and service selection.

🗺️ Concept Map

flowchart TD Compute["Azure Compute"] --> VM["Virtual Machine"] VM --> AS["Availability Set"] VM --> AZ["Availability Zone"] VM --> VMSS["VM Scale Set"] Compute --> PaaS["App Service"] Compute --> FaaS["Azure Functions"] Compute --> AKS["AKS (Kubernetes)"] Compute --> ACI["Container Instance"] VM --> Image["Marketplace / Custom Image"]

7.1 What is Azure Compute?

Azure Compute provides the actual computing power to run your applications — VMs, App Service, AKS, Azure Functions, Container Instances, and VM Scale Sets are all "compute."

🏢 Real Project Example: An SCM application: Frontend on App Service, Backend on AKS, Database on Azure SQL — three different compute/data choices for three different needs.

7.2 Virtual Machine (VM)

A VM is a software-based computer running inside Azure — you control the OS, software, security, and applications yourself. It's IaaS.

Components: VM → NIC → Managed Disk → OS → CPU → RAM.

Use cases: legacy applications, custom software, third-party apps requiring full OS access, domain controllers, jump servers.

VM Sizes ("Series")

Series Use Case
B Series Development / test (burstable, low cost)
D Series General purpose — most common for production apps
E Series Memory-intensive workloads
F Series Compute-intensive workloads
M Series SAP HANA / very large databases

🧠 Interview Angle: "Which VM series is commonly used for production applications?" → "D Series."

7.3 Availability Set vs Availability Zone (Recap)

Availability Set Availability Zone
Location Same data center Different data centers
Protects against Hardware/rack failure Entire data center failure
Availability Lower Higher

(See Part 1 for the full Fault Domain / Update Domain breakdown — the concept is identical here, just applied to compute design decisions.)

7.4 Virtual Machine Scale Set (VMSS)

VMSS automatically increases or decreases the number of VM instances based on demand.

flowchart LR Morning["Morning: 2 VMs"] --> Afternoon["Afternoon (peak): 10 VMs"] --> Night["Night: 2 VMs"]

🏢 Real Project Example: An e-commerce site during a festival sale — traffic spikes, and VMSS automatically creates more VM instances to absorb the load, then scales back down afterward.

Benefits: high availability, auto-scaling, built-in load balancing, cost efficiency (you're not paying for peak capacity 24/7).

7.5 Azure App Service

A fully managed PaaS for web applications — no VM management, no OS patching, you just deploy your code. Supports .NET, Java, Node.js, Python, PHP.

Benefits: easy deployment, auto-scaling, built-in SSL, CI/CD integration.

VM App Service
OS management You manage it Azure manages it
Service model IaaS PaaS
Control Full Less, but far less overhead

7.6 Azure Functions (Serverless)

Serverless compute — runs only when triggered, and you pay only for that execution time.

Triggers: HTTP request, Blob upload, Queue message, Timer, Event Grid.

flowchart LR Upload["Image Uploaded"] --> Fn["Azure Function\ntriggered automatically"] --> Resize["Resize Image"] --> Store["Store Result"]

7.7 Azure Kubernetes Service (AKS) — Overview

A managed Kubernetes service for running containerized applications at scale.

flowchart TD CP["Control Plane\n(Azure-managed)"] --> NP["Node Pool"] NP --> Pods["Pods"] Pods --> Containers["Containers"]

Azure manages the Control Plane; you manage your workloads (node pools, pods, containers). Benefits: container orchestration, scaling, self-healing, rolling updates.

🏢 Real Project Example: A microservices architecture — Docker containers deployed onto AKS, exposed to the internet through an Application Gateway.

7.8 Azure Container Instance (ACI)

The fastest way to run a container — no cluster required at all.

AKS ACI
Model Full Kubernetes Single container
Duration Long-running Short/temporary workloads
Use case Microservices, production apps Testing, batch jobs, temporary workloads

7.9 Marketplace Image vs Custom Image

Marketplace Image Custom Image
Provided by Microsoft/partners (Ubuntu, Windows, Red Hat, Debian...) Your own organization
Contains Base OS only OS + your software + security config + agents
Benefit Quick deployment, official & up-to-date Consistency, standardization, faster rollout

🏢 Real Project Example: A "Golden Image" — base OS + Nginx + monitoring agent + security agent — baked once, then every new VM deployed from it looks identical.

7.10 VM Extensions & Boot Diagnostics

VM Extensions automate post-deployment configuration — Custom Script Extension, Azure Monitor Agent, Dependency Agent, DSC Extension.

🏢 Real Project Example: Terraform creates the VM → a Custom Script Extension automatically installs Nginx, Docker, and the monitoring agent — no manual steps needed.

Boot Diagnostics captures VM boot logs and screenshots — essential when a VM fails to start, giving you the serial console output to diagnose why.

✅ Part 7 Best Practices

  • ✅ Use Availability Zones for production workloads.
  • ✅ Use VMSS for auto-scaling applications.
  • ✅ Prefer App Service for web apps when OS-level access isn't required.
  • ✅ Use AKS for microservices / containerized applications.
  • ✅ Use Custom Images for standardized VM deployments.
  • ✅ Always enable Boot Diagnostics.
  • ✅ Use Premium SSD for production workloads.
  • ✅ Integrate with Azure Monitor and Defender for Cloud.

🖥️ Hands-On: Create a Virtual Machine in the Portal

  1. In the Portal search bar, type "Virtual machines" → + Create → Azure virtual machine.
  2. On Basics: choose Subscription, Resource Group, VM name, Region, and Image (e.g. Ubuntu Server or Windows Server), then a Size (e.g. a D-series for general purpose).
  3. Set the Administrator account (SSH key for Linux, or username/password for Windows).
  4. On Disks: choose Premium SSD for production.
  5. On Networking: select your VNet/Subnet — and consider not assigning a Public IP if Bastion will be used instead.
  6. On Management: enable Boot diagnostics.
  7. Select Review + create, then Create.

💡 Try it yourself: After the VM is created, go to Extensions + applications → add the Custom Script Extension → point it at a simple script that installs Nginx. This is exactly the automation pattern Terraform pipelines use in real projects.

🧠 Part 7 — Interview Questions

What is Azure Compute?

The set of services that provide on-demand computing resources — VMs, containers, and serverless functions — to run applications in the cloud.

What is a Virtual Machine?

An IaaS offering where Azure provides the underlying infrastructure while the customer manages the operating system and applications running on top of it.

What is a VM Scale Set?

A service that automatically increases or decreases the number of VM instances based on real-time demand, providing auto-scaling and high availability.

What is Azure App Service?

A fully managed PaaS for hosting web applications — Azure handles the OS, patching, and infrastructure, so developers only manage their code.

What is Azure Functions?

A serverless compute service that runs code only when triggered (HTTP, Blob upload, Queue message, Timer, Event Grid), and you pay only for actual execution time.

What is AKS?

Azure Kubernetes Service — a managed Kubernetes offering where Azure manages the Control Plane while you manage your node pools, pods, and containers.

What is Azure Container Instance?

The fastest way to run a container in Azure without provisioning a full cluster — ideal for testing, batch jobs, and temporary workloads.

What is the difference between a Marketplace Image and a Custom Image?

A Marketplace Image is a ready-made base image provided by Microsoft or partners. A Custom Image is built by your own organization, pre-loaded with your software, agents, and security configuration for consistent deployment.

What are VM Extensions?

Small agents that automate post-deployment configuration tasks on a VM — such as running a custom script, or installing a monitoring agent — right after provisioning.

What is Boot Diagnostics?

A feature that captures a VM's boot logs and screenshots, used to troubleshoot why a VM is failing to start.

🧩 Part 7 — Scenario-Based Questions

Your application traffic increases from 500 users to 10,000 users during a sale. How will you handle it?

Deploy the application on a VM Scale Set or AKS with autoscaling enabled — it automatically adds instances during high traffic and scales back down as demand decreases.

Developers need a web application hosting platform but don't want to manage VMs or operating systems. Which service will you recommend?

Azure App Service — it's PaaS, so Azure manages the OS, patching, and infrastructure while developers focus purely on the application.

Your company has 100 virtual machines that all require the same software and security configuration. How will you deploy them consistently?

Create a Custom Image ("Golden Image") containing the required software and security settings, then deploy all VMs from that single image.

A virtual machine is not starting after a reboot. How will you troubleshoot it?

Check Boot Diagnostics, review the serial console output and screenshots, verify the OS disk status, and review Activity Logs to identify the startup issue.

Your application processes uploaded files only when a new file arrives in Blob Storage. Which compute service will you choose?

Azure Functions with a Blob Storage trigger — it runs only when a file is uploaded and is cost-effective for event-driven workloads.

📋 Part 7 — Quick Revision

  • Azure Compute = services that run applications.
  • Virtual Machine = IaaS, full OS control. VM Size = CPU/RAM/disk/network capacity (B/D/E/F/M series).
  • Availability Set = protects against hardware/maintenance failure (same data center). Availability Zone = protects against data center failure (different data centers).
  • VM Scale Set = automatic VM scaling.
  • App Service = PaaS for web apps. Azure Functions = serverless, event-driven compute.
  • AKS = managed Kubernetes. ACI = run a container without a cluster.
  • Marketplace Image = Microsoft-provided base. Custom Image = your organization's standardized image.
  • VM Extensions = automate post-deployment configuration. Boot Diagnostics = startup troubleshooting.
  • Premium SSD = the recommended disk tier for production.
