Part 9 — Monitoring & Observability

🎯 Goal: Monitor Azure resources and applications, and troubleshoot production issues. At the 5+ year interview level, expect "how do you detect a production issue?" and "VM CPU hit 100% — what now?", not just definitions.

🗺️ Concept Map

flowchart TD Mon["Azure Monitor"] --> Metrics["Metrics\n(numbers)"] Mon --> Logs["Logs\n(detailed events)"] Logs --> LAW["Log Analytics Workspace\n(KQL queries)"] Mon --> AMA["Azure Monitor Agent"] Mon --> DS["Diagnostic Settings"] Mon --> AL["Activity Log\n(control plane)"] Mon --> Alerts["Alerts"] Alerts --> AG["Action Group"] Mon --> AI["Application Insights"] Mon --> WB["Workbooks"]

9.1 What is Monitoring?

Monitoring means continuously checking the health and performance of Azure resources — is the VM running, is the app healthy, is CPU high, is disk full, is the network slow, is the app throwing errors?

flowchart LR subgraph Without["Without Monitoring"] P1["Problem"] --> C["Customer Complains"] --> B["Business Loss"] end subgraph With["With Monitoring"] P2["Problem"] --> A["Alert Generated"] --> E["Engineer Fixes It Quickly"] end

🧠 Interview Angle: "Azure Monitoring is the process of collecting, analyzing, and visualizing resource health, performance, logs, and alerts to ensure applications run reliably."

9.2 Azure Monitor

Azure Monitor is the central monitoring service in Azure — it collects Metrics, Logs, Alerts, Resource Health, and Performance Data from almost every Azure resource: VMs, Storage Accounts, AKS, App Service, SQL Database, Azure Firewall, Application Gateway, Azure Functions, and more.

flowchart LR Res["Azure Resources"] --> AM["Azure Monitor"] AM --> M["Metrics"] AM --> L["Logs"] AM --> Al["Alerts"] AM --> Dash["Dashboards"]

9.3 Metrics vs Logs

Metrics Logs
Type Numeric performance values Detailed event records
Examples CPU usage, disk IOPS, network traffic, request count, response time VM restart, login, application error, firewall logs, SQL queries
Speed Near real-time, lightweight Richer, used for deep analysis
Used for Alerting Troubleshooting

🧠 Interview Angle: "Metrics are numeric data used for fast monitoring and alerting. Logs are detailed records used for deeper troubleshooting."

9.4 Log Analytics Workspace & KQL

Log Analytics Workspace is the central place where Azure stores and lets you query logs, using KQL (Kusto Query Language).

flowchart TD VM["VM"] --> LAW["Log Analytics Workspace"] Storage["Storage"] --> LAW AKS["AKS"] --> LAW FW["Firewall"] --> LAW 
AzureActivity
| limit 10

(returns the 10 most recent Azure activity log entries)

9.5 Azure Monitor Agent (AMA)

AMA collects monitoring data from Virtual Machines — performance data, event logs, syslogs — and sends it to Azure Monitor. It's the modern replacement for older, legacy monitoring agents.

flowchart LR VM["Linux VM"] --> AMA["Azure Monitor Agent"] --> LAW["Log Analytics"] --> AM["Azure Monitor"]

9.6 Diagnostic Settings

Diagnostic Settings send logs and metrics from an Azure resource to one or more destinations: Log Analytics Workspace, Storage Account, or Event Hub.

🧠 Interview Angle: "Why enable Diagnostic Settings?" → "To collect logs and metrics for monitoring, troubleshooting, auditing, and compliance."

9.7 Activity Log

Activity Log records management operations — Create VM, Delete Storage, Assign RBAC, Create NSG, Policy Changes. It tracks Control Plane operations only — not application-level logs.

🏢 Real Project Example: A developer deleted a Storage Account → check the Activity Log → see exactly who deleted it, and when.

9.8 Alerts & Action Groups

Alerts automatically notify engineers when a condition is met (e.g. CPU > 80%). Action Groups define what happens after an alert fires: Email, SMS, phone call, Webhook, Azure Function, Logic App, or Automation Runbook.

flowchart LR Cond["CPU > 90%"] --> Alert["Alert Fires"] --> AG["Action Group"] --> Notify["Email + Teams + Webhook"]

Alert Types: Metric Alert, Log Alert, Activity Log Alert, Resource Health Alert, Smart Detection (via Application Insights).

9.9 Application Insights

Very important topic. Application Insights monitors your application's behavior specifically — Response Time, Failed Requests, Exceptions, Dependencies, Availability, User Requests.

🏢 Real Project Example: A website becomes slow → Application Insights shows a slow SQL query is the culprit → problem identified without guesswork.

🧠 Interview Angle: "Application Insights provides deep monitoring for application performance and helps identify failures and performance bottlenecks."

9.10 Workbooks

Workbooks create interactive dashboards — combining metrics and logs into one view (VM CPU, memory, failed logins, network usage, AKS health, all in one place).

Complete Monitoring Flow

flowchart TD Res["Azure Resources"] --> AMA["Azure Monitor Agent"] --> AM["Azure Monitor"] --> LAW["Log Analytics"] --> Alerts["Alerts"] --> AG["Action Group"] --> Team["DevOps Team"]

🏢 Real Project Example: Production AKS cluster → application crashes → Application Insights detects it → data flows into Log Analytics → Alert fires → Action Group sends Email to DevOps → issue fixed.

✅ Part 9 Best Practices

  • ✅ Create Log Analytics Workspaces sensibly (e.g. one per environment or region, per your org's design).
  • ✅ Enable Diagnostic Settings on all critical resources.
  • ✅ Use the modern Azure Monitor Agent (AMA).
  • ✅ Create alerts for CPU, Disk, Memory, Failed Logins, Availability, and HTTP 5xx errors.
  • ✅ Enable Application Insights for every application.
  • ✅ Monitor security events, not just performance.
  • ✅ Build Workbooks for at-a-glance dashboards.

🖥️ Hands-On: Create a Metric Alert Rule

  1. Go to your resource (e.g. a VM) → Monitoring → Alerts → + Create → Alert rule.
  2. Under Condition, select a signal — e.g. Percentage CPU.
  3. Set the threshold logic — e.g. Greater than 80%, evaluated every 5 minutes over a 15-minute window.
  4. Under Actions, select + Create action group — add an email/SMS/Teams webhook recipient.
  5. Name the alert rule (e.g. alert-vm-high-cpu) and select Create.

💡 Try it yourself: Create a Log Analytics Workspace first (search "Log Analytics workspaces" → + Create), then enable Diagnostic Settings on a resource to send its logs there. Run the query AzureActivity | limit 10 in the workspace's Logs blade to see raw KQL in action.

🧠 Part 9 — Interview Questions

What is Azure Monitor?

The central Azure service that collects metrics, logs, alerts, and resource health data from nearly every Azure resource, providing monitoring, alerting, and troubleshooting capability.

What are Metrics?

Numerical performance values collected over time — like CPU usage, disk IOPS, or request count — used for near-real-time monitoring and alerting.

What are Logs?

Detailed records of events — like a VM restart, a login, or an application error — used for deeper troubleshooting and analysis.

What is a Log Analytics Workspace?

A central store for monitoring logs, queried using Kusto Query Language (KQL), where data from VMs, AKS, Storage, and other resources can be aggregated and analyzed.

What is Azure Monitor Agent (AMA)?

The modern agent that collects performance data, event logs, and syslogs from Virtual Machines and sends them to Azure Monitor.

What are Diagnostic Settings?

The configuration that routes a resource's logs and metrics to a destination — Log Analytics Workspace, Storage Account, or Event Hub — for monitoring, auditing, or compliance.

What is the Activity Log?

A log that records Control Plane management operations — like creating a VM or deleting a resource — including who performed the action and when. It does not contain application-level logs.

What is Application Insights?

An Application Performance Monitoring (APM) service that tracks response time, failed requests, exceptions, and dependencies to help identify application-level problems.

What are Alerts?

Rules that automatically notify engineers when a defined condition is met — like CPU exceeding 80% — triggering a configured Action Group.

What is an Action Group?

A reusable definition of what should happen when an alert fires — send an email, SMS, trigger a webhook, run an Azure Function, or invoke a Logic App / Automation Runbook.

🧩 Part 9 — Scenario-Based Questions

Your production VM's CPU stays above 90% for 15 minutes. How will you detect and notify the team?

Create a Metric Alert based on CPU percentage, with an Action Group that sends an email or Microsoft Teams notification to the DevOps team when it fires.

A developer accidentally deleted a Network Security Group. How will you identify who performed the action?

Check the Azure Activity Log — it records Control Plane operations including resource creation, modification, and deletion, along with who performed them.

Users report the web application is slow, but VM CPU looks normal. Which service will you use?

Application Insights — to analyze response time, failed requests, dependencies, and exceptions, which helps pinpoint issues like a slow database query that CPU metrics alone wouldn't reveal.

Your security team needs to keep firewall logs for auditing. How will you configure Azure?

Enable Diagnostic Settings on Azure Firewall and send the logs to a Log Analytics Workspace for querying, and optionally archive them to a Storage Account for long-term retention.

You need a dashboard showing CPU usage, failed logins, and storage utilization for production resources. Which feature will you use?

An Azure Workbook — it combines metrics and log queries into a single interactive dashboard.

📋 Part 9 — Quick Revision

  • Azure Monitor = the central monitoring service.
  • Metrics = numeric performance data. Logs = detailed event records.
  • Log Analytics Workspace = central log storage, queried with KQL.
  • Azure Monitor Agent (AMA) = collects VM telemetry.
  • Diagnostic Settings = routes logs/metrics to Log Analytics, Storage, or Event Hub.
  • Activity Log = Control Plane operations only.
  • Application Insights = application performance monitoring (APM).
  • Alerts = detect issues automatically. Action Group = defines what happens next.
  • Workbooks = interactive monitoring dashboards.
