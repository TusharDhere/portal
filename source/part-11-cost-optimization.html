Part 11 — Cost Optimization

🎯 Goal: Learn to monitor, control, and optimize Azure costs. At the 5+ year interview level, it's not enough to deploy resources — you're expected to make them cost-efficient too.

🗺️ Concept Map

11.1 Azure Pricing Model

Azure follows a Pay-As-You-Go model — you pay only for what you actually use. Pricing depends on VM size, storage type, data transfer, region, and how long a resource actually runs.

🧠 Interview Angle: "Azure follows a Pay-As-You-Go pricing model where customers are charged based on actual resource usage." A VM running 24 hours costs more than the same VM stopped (deallocated) — deallocating, not just powering off inside the OS, is what actually stops billing for compute.

11.2 Cost Management + Billing

Helps organizations monitor costs, analyze spending, forecast future costs, and optimize resources. Key features: Cost Analysis, Budgets, Alerts, Reports, Forecast.

Cost Analysis

Shows detailed spending, filterable by Subscription, Resource Group, Service, Region, or Tags.

Budgets

Define a spending limit and get alerted as you approach it.

🏢 Real Project Example: Monthly budget = ₹50,000. Alert fires at 80% spent, another alert at 100% — giving the team advance warning before overspending, not just a post-mortem.

Cost Alerts

Automatically notify administrators when spend crosses a threshold — e.g. the Finance team receives a monthly cost alert email automatically.

11.3 Azure Advisor

Azure Advisor analyzes your resources and gives recommendations across five pillars: Cost, Performance, Security, Reliability, Operational Excellence.

Typical cost recommendations: resize an oversized VM, delete unused disks, remove idle Public IPs, purchase Reserved Instances.

11.4 Reservations vs Savings Plans vs Spot VMs

Three different ways to save money on compute — each fits a different workload pattern.

Reserved Instances Savings Plan Spot VM
Commitment 1 or 3 years, fixed resource 1 or 3 years, committed hourly spend None
Flexibility Lower — locked to a specific VM type/region Higher — flexible across eligible compute Highest — but Azure can evict anytime
Best for Predictable, 24×7 production workloads Changing/evolving workloads that still run steadily Testing, CI/CD, batch jobs, temporary workloads
Risk None (guaranteed capacity) None (guaranteed capacity) Can be evicted when Azure needs the capacity back

⚠️ Common Mistake: Never use Spot VMs for production applications or critical databases — they can be evicted without notice whenever Azure needs the capacity.

🧠 Interview Angle: "Reserved Instances lock in a specific resource for predictable savings. Savings Plans offer more flexibility across eligible services based on committed hourly spend. Spot VMs are cheapest but can be evicted anytime — great for interruption-tolerant workloads only."

11.5 Auto Shutdown

Automatically shuts down development/test VMs after office hours (e.g. 7 PM) and they're started again the next morning — a simple, high-impact way to cut non-production compute cost.

11.6 Resource Tagging (for Cost Allocation)

Tags let you break down spend by Environment, Owner, Project, Department, Application — directly feeding into Cost Analysis reports.

✅ Best Practice: Every resource should carry standard tags — this is the only practical way to answer "how much does each team/project actually cost us?" at scale.

11.7 Cost Governance

Policies that keep spending under control — approved VM sizes only, budget limits, mandatory tagging, scheduled resource cleanup, regular cost reviews.

🏢 Real Project Example: Policy: "Only D-Series VMs allowed." A developer requests an M-Series VM → denied automatically by Azure Policy, before it ever gets provisioned.

Enterprise Cost Optimization Checklist

  1. Delete unused resources — orphaned Public IPs, unattached NICs, unused disks, old snapshots.
  2. Right-size VMs — don't run a 16-vCPU VM for a 2-vCPU workload.
  3. Use Auto Shutdown on development VMs only.
  4. Use Reserved Instances for predictable 24×7 production workloads.
  5. Use Spot VMs for testing, batch jobs, and CI/CD.
  6. Use Lifecycle Management to move old blobs Hot → Cool → Archive.
  7. Monitor cost monthly — Cost Analysis, Advisor, Budgets, every month, not just once at setup.

✅ Part 11 Best Practices

  • ✅ Create a Budget for every subscription.
  • ✅ Configure Cost Alerts.
  • ✅ Review Azure Advisor recommendations regularly, not just once.
  • ✅ Enable Auto Shutdown for Dev/Test VMs.
  • ✅ Right-size VMs based on actual utilization data.
  • ✅ Use Reserved Instances for predictable workloads, Savings Plans for flexible ones.
  • ✅ Delete unused resources proactively.
  • ✅ Apply standard Resource Tags everywhere.
  • ✅ Review spending every month — cost drift is gradual and easy to miss.

🖥️ Hands-On: Create a Budget in the Portal

  1. Navigate to your Subscription (or a Resource Group) → select Budgets from the left menu.

  1. Select + Add. Confirm the scope, add any filters (e.g. only a specific Resource Group or service), name the budget, and choose a reset period — Monthly, Quarterly, or Annually.
  2. Set the budget amount — the Portal shows a graph based on your forecasted cost to help you pick a sensible number.

  1. Select Next to configure alerts — add at least one threshold (e.g. 80%) and an email address.

  1. Select Create. Your budget now appears in Cost Analysis, tracked against real spending.

💡 Try it yourself: Go to Azure Advisor (search the Portal for it) → open the Cost tab → look through the actual recommendations for your subscription (oversized VMs, unused disks, idle Public IPs). This is the exact workflow a DevOps engineer runs monthly.

🧠 Part 11 — Interview Questions

What is Azure Cost Management?

A set of tools that give visibility into cloud spending and help monitor, analyze, forecast, and optimize Azure costs.

What is Cost Analysis?

A feature that shows detailed spending breakdowns, filterable by subscription, resource group, service, region, or tags.

What is Azure Advisor?

A service that analyzes your Azure resources and provides recommendations across Cost, Performance, Security, Reliability, and Operational Excellence.

What are Budgets?

Defined spending limits, scoped to a subscription, resource group, or management group, used to track and control cost with configurable alert thresholds.

What are Cost Alerts?

Notifications automatically sent to administrators or finance teams when spending crosses a defined threshold of a budget.

What are Reserved Instances?

A pricing option where you commit to using a specific resource for 1 or 3 years in exchange for significantly lower cost — best for predictable, always-on production workloads.

What is Azure Savings Plan?

A flexible discount model based on committing to a fixed hourly spend across eligible compute services for 1 or 3 years, offering more flexibility than Reserved Instances.

What is a Spot VM?

A very low-cost VM that uses Azure's spare, unused capacity — but Azure can evict it at any time when that capacity is needed elsewhere, so it's unsuitable for production.

What is Auto Shutdown?

A feature that automatically powers off development/test VMs after a scheduled time (e.g. after office hours) to reduce unnecessary compute costs.

Why are Resource Tags important for cost management?

They allow spending to be broken down and reported by dimensions like Environment, Owner, Project, or Department — without tags, cost attribution across teams is essentially impossible.

🧩 Part 11 — Scenario-Based Questions

Your development VMs run 24 hours a day, but developers only use them during office hours. How will you reduce the cost?

Enable Auto Shutdown so the VMs stop automatically after working hours — this removes unnecessary compute cost with no impact on the developers' actual working time.

Your production application runs continuously throughout the year. Which pricing option will you choose?

Reserved Instances — the workload is predictable and runs 24×7, so a 1- or 3-year reservation delivers significant savings over Pay-As-You-Go.

Your CI/CD pipeline needs temporary VMs for build jobs. Which compute option can reduce costs?

Spot Virtual Machines — build jobs are temporary and can tolerate interruptions, making Spot VMs a cost-effective fit.

Your finance team wants to know how much each department spends in Azure. How will you achieve this?

Apply Resource Tags such as Department, Project, and Environment to all resources, then use Cost Analysis to filter and report spending by those tags.

Your monthly Azure bill increased unexpectedly. How will you investigate it?

Review Cost Analysis to identify which resources or services increased in cost, check Azure Advisor recommendations, remove unused resources, right-size VMs where needed, and verify whether new deployments caused the increase.

📋 Part 11 — Quick Revision

  • Pay-As-You-Go = pay only for what you use.
  • Cost Management = monitor and optimize spending. Cost Analysis = detailed spend reports.
  • Budget = a planned spending limit. Cost Alerts = notifications at spend thresholds.
  • Azure Advisor = optimization recommendations across 5 pillars.
  • Reserved Instances = lower cost, fixed resource, predictable 24×7 workloads.
  • Savings Plan = flexible discount via committed hourly spend.
  • Spot VM = cheapest, but can be evicted — never for production.
  • Auto Shutdown = cuts Dev/Test VM cost automatically.
  • Resource Tags = enable cost allocation & reporting.
  • Cost Governance = policies (approved sizes, budgets, cleanup, reviews) that keep spend under control.
